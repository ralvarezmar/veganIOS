# Darwin Spring Boot Business Events ![6.3.4](https://img.shields.io/badge/6.3.4-FF073D)

![Current](https://img.shields.io/badge/CURRENT-30FF24) ![GA](https://img.shields.io/badge/GA-C81D11)

## Description

The `Darwin Spring Boot Business Events` library provides the necessary functionality to generate `Business Events` that contain the functional information associated with a REST request.
In addition, it will provide an annotation to mark public methods in the service layer components to generate these business events.

The event format is based on an extension of the [CloudEvents](https://cloudevents.io/) specification, which allows us to describe events in a common, accessible and portable way.

!!! info "Important"

    This library is intended to automate its use in environments with `Brokers Kafka` through `Spring Kafka`. This library is not intended for use on systems other than `Spring Kafka`, such as `Spring Cloud Stream`. If you have
    any questions, please open a ticket to architecture support.

## Business Events Functionality

!!! info "Important"

    If you need information about the `darwin-spring-boot-events` library functionality, you can consult the [Events documentation](../darwin-spring-boot-events/README.md).

**Business event** is a functionality that allows sending business events to a Kafka topic in **CloudEvent** format serialized using **Avro**.

!!! warning

    It is mandatory to configure both the hosts of the Business Event brokers and the URL of the Schema registry. It any of these properties are not set in the properties file, the application will fail. In addition, during the
    configuration time, it validates the connection with the Kafka brokers, if it is not possible to connect with any broker, the application will fails during the start-up.

!!! note

    The resilience level used for sending these events is `deliveredguarantee` regardless of the resilience level configured in the `darwin.events.resilience-mode` property.

The format of the event sent is:

          }

        {
          "doc": "Component identifier (e.g. microservice) that publishes the business event",

            "type": "string"
          }
        },
        {
          "default": null,
          "doc": "API or Microservice input data",
          "name": "input",
          "type": [
            "null",
            {
              "avro.java.string": "String",
              "type": "string"
            }
          ]
        },
        {
          "default": null,
          "doc": "API or Microservice output data",
          "name": "output",
          "type": [

!!! info "Important"

    The sending of the event will be done in background and will not be blocking. In case of failure it will leave a trace in the log but will not stop the execution with an error.

!!! note

    The service will use as value of **appKey** the value configured in the darwin property `darwin.app-key` and as **appName** the value of the environment variable `APP_NAME`.

There are three ways to send **Business Events**:

#### Manual

Darwin configures a `ReactiveBusinessEventService` / `BusinessEventService` service that can be used directly by the application.

The service expects a minimum of four fields:

- **input**: String with the input of the service

- **output**: String with the response of the service

- **operation**: String with the identifier of the operation executed

- **additionalInfo**: Map&lt;String, Object&gt; with additional business information that you want to store

There is a second method with two extra fields for [obfuscation](#obfuscation).

#### Automatic

A series of endpoints and verbs can be configured for http calls so that these calls are automatically sent as a business event.

For this purpose it is necessary to configure the `darwin.events.business.filter` properties.

!!! note

    If it is required to generate business events from a http ***GET*** method, this must be added to `darwin.events.business.filter.http-verbs` property together with the rest of required http verbs.

The fields with operation information for the business event will have these values:

- **input**: body of the request as Json String.

- **output**: endpoint's response as Json String.

- **operation**: composed with request information as *HTTP\_METHOD#requestPath*.

#### Annotations

You can mark with the `@BusinessEvents` annotation any public method of a service to automatically send the business event or use the class level annotation and all public methods of the class will send a business event.

!!! tip "Caution"

    If the method has any reactive-type parameter (Mono, Flux, etc.) its value cannot be obtained and **null** will be used instead.

The fields with operation information for the business event will have these values:

- **input**: key/value pairs with method arguments as Json String.

- **output**: method's response as Json String.

- **operation**: composed with method information as *ClassSimpleName#methodName*.

#### Obfuscation

Business events functionality offers obfuscation feature for hiding sensible information on the input and the output fields. The `ObfuscateBusinessEvent` annotation and the business Event services accept a set of sensitive fields as input parameter.

For both the automatic instrumentation and the use of the Business Event annotation, it is possible to use the `ObfuscateBusinessEvent` on the methods or on the top class in order to define the sensitive fields for each operation where it is
necessary to apply the obfuscation. In all the cases, the data will be parsed to JSON String format and hidden the values of the sensible fields defined.

!!! note

    For more information about how to use the `ObfuscateBusinessEvent` annotation for automatic Business Events, consult the 
    [How to obfuscate sensible information on automatic Business Events](#how-to-obfuscate-sensible-information-on-automatic-business-events)
    section

!!! note

    For more information about how to use the `ObfuscateBusinessEvent` annotation together the `BusinessEvents` annotation, consult the [How to define sensible fields in the Business Event annotation](#how-to-define-sensible-fields-in-the-business-event-annotation) section

The annotation (`@ObfuscateBusinessEvent`) provide two parameters (`sensibleInput` and `sensibleOutput`) in order to define the sensible fields to hide.

!!! info "Important"

    Keep in mind that the http verb defined on the controller method have to be included in the list of the http-verbs supported by the automatic instrumentation (`darwin.events.business.filter.http-verbs`).

Business events services (both **Reactive** and **Servlet** flavours) provide a method that they accept as input parameters two array of the sensible fields: the first array is for the input data, and the second one is for the output data.

!!! note

    For more information about how to hide sensible information using the Business events services, consult the 
    [How to manually send a Business Event hiding sensible information](#how-to-manually-send-a-business-event-hiding-sensible-information) section

In any case, obfuscation allows developers to use two ways in order to define the information that have to be hidden.

1. Using accurate expressions through [Jayway JsonPath specification](https://github.com/json-path/JsonPath#getting-started).

2. Simple references of the fields in order to hide all their appearances.

## Installation and configuration

If you want to add the business events functionality you have to add the following dependency. **Darwin Spring Boot Business Events**:

    <dependency>
        <groupId>com.santander.darwin</groupId>
        <artifactId>darwin-spring-boot-starter-business-events</artifactId>
    </dependency>

It is not necessary to include the `darwin-spring-boot-starter-events` dependency to use `darwin-spring-boot-starter-business-events` or the other way around.

!!! note

    We have separated the events functionality into two starters to limit the number of dependencies that are added to projects

##### Disable the validation of the connection with Kafka

The Kafka connection is validated during the configuration time in order to know if the instances of the brokers are available. In case of the validation fails, the start-up of the application will be stopped. For disabling this feature, the
following property can be configured for skipping this validation:

    darwin:
      events:
        business:
          connection-validation: false
          servers: ${env.business-event.servers}
          schema-registry:
            url: ${env.business-event.registry.url}
          topic: ${env.business-event.topic}
          properties:
            security.protocol: ${env.business-event.security-protocol}
            sasl.mechanism: ${env.business-event.sasl-mechanism}
            sasl.jaas.config: ${env.business-event.sasl-jaas}
            basic.auth.credentials.source: ${env.business-event.registry.source}
            basic.auth.user.info: ${env.business-event.user}

## Native compilation support

This library can be used on micros that are compiled to a native image with graalvm native.

To use it in native mode we have to exclude logging dependency.

        <dependency>
            <groupId>com.santander.darwin</groupId>
            <artifactId>darwin-spring-boot-starter-business-events</artifactId>
            <exclusions>
                <!-- To avoid load log4j in native profile -->
                <exclusion>
                    <groupId>com.santander.darwin</groupId>
                    <artifactId>darwin-spring-boot-starter-logging</artifactId>
                </exclusion>
            </exclusions>
        </dependency>

### Limitations

- Logging related functionality is not supported.

## Use cases

### How to manually send a Business Event

In case we want to send a Business Event we can do it using the service **ReactiveBusinessEventService** or **BusinessEventService** depending if we are in a reactive or servlet environment.

#### Reactive

    @Autowired
    ReactiveBusinessEventService reactiveBusinessEventService; (1)

    @GetMapping("/manual")
    public Mono<Void> receive(@RequestHeader HttpHeaders headers) {
        return reactiveBusinessEventService.send("input", "output", "operationName",
                Map.of("key1","value1", "key2","value2")); (2)
    }

1. Get the service

2. Send the event

#### Servlet

    @Autowired
    BusinessEventService businessEventService; (1)

    @GetMapping("/manual")
    public void receive(@RequestHeader HttpHeaders headers) {
        businessEventService.send("input", "output", "operationName",
                Map.of("key1","value1", "key2","value2")); (2)
    }

1. Get the service

2. Send the event

### How to use annotations to send a Business Event

For the execution of a method to send a business event for each execution, the method must be a public method of a bean that is called from outside the bean itself and the method must be annotated with the `@BusinessEvents` annotation, you can also
put the annotation at the class level and it would be equivalent to annotating all public methods.

**Example of annotation with `@BusinessEvents` in a method**

    @BusinessEvents
    public String publicBusiness(String name) {
        var newName = this.privateBusiness(name);
        log.info("Business logic");
        return newName;
    }

**Example of annotation with `@BusinessEvents` in a class**

    @Slf4j
    @Service
    @BusinessEvents
    public class BusinessEventMarkedMethod {

        public String publicBusiness(String name) {
            var newName = this.privateBusiness(name);
            log.info("Business logic");
            return newName;
        }

        private String privateBusiness(String name) {
            log.info("private Business logic");
            return "hello" + newName;
        }
    }

In the last example only *publicBusiness* executions will send a BusinessEvent.

### How to define sensible fields in the Business Event annotation

The information sent inside the business events could contain sensible data that it cannot be exposed. In order to avoid sending confidential information, the `ObfuscateBusinessEvent` annotation can be used together with the `BusinessEvents`
annotation. The obfuscation annotation provides two parameters for defining that fields have to hide. The fields defined in these parameters (`sensibleInput` and `sensibleOutput`) are searched inside data structure (input and output data) and their
values are obfuscated. Finally, the Business Event service generates a message where the structure of data, both input and output data, have the confidential information obfuscated with `****`.

The implementation that it is charge of searching the fields inside data structure and changing the values for the symbols of obfuscation is based on `Jayway JsonPath`. This library provides the use of expressions in order to define the path inside
JSON structure. Additionally, if the name of the field is defined in plain format i.e. simply the name of the fields without using a path expression, the implementation will hide all the appearances of these fields inside data structure.

!!! note

    For more information about how to define JSON paths expressions, you can look up the documentation of the [Jayway JsonPath](https://github.com/json-path/JsonPath#getting-started) library.

**Example of the `BusinessEvents` annotation with `@ObfuscateBusinessEvent` defining sensible fields**

    import org.springframework.stereotype.Service;

    @Service
    public class BusinessEventMarkedMethod {

        @BusinessEvents
        @ObfuscateBusinessEvent(sensibleInput = { "name" }, sensibleOutput = { "someField" })
        public String publicBusiness(String name) {
            return this.privateBusiness(name);
        }
    }

For this example, two sensible fields have been defined: ***name*** for input data, and ***someField*** for output data.

**Example of the `BusinessEvents` annotation with `@ObfuscateBusinessEvent` defining sensible fields in a simple way**

    import lombok.AllArgsConstructor;
    import lombok.Data;
    import lombok.NoArgsConstructor;
    import org.springframework.stereotype.Service;

    @Service
    public class BusinessEventMarkedMethod {

        @BusinessEvents
        @ObfuscateBusinessEvent(sensibleInput = { "username" }, sensibleOutput = { "name" })
        public DataUser publicBusiness(String username) {
            return new DataUser(username, new User(1, username));
        }
    }

    @Data
    @AllArgsConstructor
    @NoArgsConstructor
    class DataUser {
        private String name;
        private User user;
    }

    @Data
    @AllArgsConstructor
    @NoArgsConstructor
    class User {
        private int id;
        private String name;

    }

Here we must keep in mind that if the sensible field is defined in a simple way (**not as an expression**), the implementation will hide all the appearances of that field in the data structure. In the previous example, the result will be processed
and all the occurrences of the field ***name*** will be hidden with the symbols of the obfuscation.

The output field in the business event will have the following form:

    {
      "name": "****",
      "user": {
        "name": "****",
        "id": 1
      }
    }

**Example of the `BusinessEvents` annotation with `@ObfuscateBusinessEvent` defining sensible fields with JsonPath expression.**

    import lombok.AllArgsConstructor;
    import lombok.Data;

    @Service
    @BusinessEvents(sensibleInput = { "$.accountNumber" }, sensibleOutput = { "$.idAccount" })
    public class BusinessEventMarkedMethod {

        public User generateUser(String username, int accountNumber) {
            return new User(name, id);
        }
    }

    @Data
    @AllArgsConstructor
    public static class User {

        private String name;

        private int idAccount;
    }

For the input parameters, the field ***accountNumber*** will be hidden. The input data event will have this form:

    {
      "username": "Peter",
      "accountNumber": "****"
    }

For the result of the execution method, the field ***idAccount*** inside ***User*** entity will be hidden. The output data event will have this form:

    {
      "name": "Peter",
      "idAccount": "****"
    }

### How to manually send a Business Event hiding sensible information

This time, we want to send a Business Event sensitizing confidential information that we don't want to expose. We can do it using the service **ReactiveBusinessEventService** or **BusinessEventService** depending on if we are in a reactive or
servlet environment.

#### Reactive

    import org.springframework.web.bind.annotation.RestController;

    @RestController
    public class BusinessService {

        @Autowired
        ReactiveBusinessEventService reactiveBusinessEventService; (1)

        @GetMapping("/manual")
        public Mono<Void> receive(@RequestHeader HttpHeaders headers) {
            return reactiveBusinessEventService.send( (4)
                "{\"user\":\"Paul\",\"identityCard\":\"00000001A\"}",
                "{\"user\":\"Paul\",\"identityCard\":\"00000001A\",\"creditCard\":\"100000001\"}",
                "operationName",
                Map.of("key1","value1", "key2","value2"),
                new String[] {"$.identityCard"}, (2)
                new String[] {"$.identityCard", "$.creditCard" }); (3)
        }
    }

1. Get the service

2. Define sensible fields for the input

3. Define sensible fields for the output

4. Send the event

For the input parameters, the field ***identityCard*** will be hidden. The input data event will have this form:

    {
      "user": "Paul",
      "identityCard": "****"
    }

For the body of the response, the fields ***identityCard*** and ***creditCard*** will be hidden. The output data event will have this form:

    {
      "name": "Paul",
      "identityCard": "****",
      "creditCard": "****"
    }

### How to obfuscate sensible information on automatic Business Events

Thanks to the `ObfuscateBusinessEvent` annotation, it is possible to hide sensible information on the input and the output fields inside Business Events when these are generated by the automatic instrumentation.

The annotation allow us to mark any controller method annotated with `@GetMapping`, `@PostMapping`, `@PatchMapping`, `@PutMapping`, and `@RequestMapping` inside a `@RestController` class. Also, it is possible to use it at the top class level in
order to set a common sensible fields for all the controller methods (`@GetMapping`, `@PostMapping`, `@PatchMapping`, `@PutMapping`, and `@RequestMapping`) defined in the class (`@RestController`). If some endpoints defined in the rest controller
class is present in the list of the Business Events endpoints (`darwin.events.business.filter.end-points`), and the annotation is used at the top class level or for marking the controller method, when the Business Events is generated, both the input
and output will be processed and the sensible fields will be hidden. In order to set the sensible fields, the annotation (`@ObfuscateBusinessEvent`) provides two parameters (sensibleInput and sensibleOutput) in order to define the sensible fields to
hide.

!!! note

    The annotation `@ObfuscateBusinessEvent` can be used in both `Reactive` web applications and `Servlet` web applications.

**Example of the `ObfuscateBusinessEvent` annotation at the top class level.**

First, the path has to be defined inside the list of the Business Events automatic endpoints as follows:

    darwin:
      events:
        business:
          filter:
            endpoints:
              - /top-level-class/be-sensible
              - /top-level-class/get-be-sensible

After, the annotation is used for marked the top class of the rest controller component. In this case, both the controller methods manage endpoints that they are defined in the list of Business Events automatic endpoints, so both of them generate
Business Events and their input and output fields are sensitised.

    import com.santander.darwin.events.business.annotation.ObfuscateBusinessEvent;
    import org.springframework.web.bind.annotation.RequestBody;
    import org.springframework.web.bind.annotation.RequestMapping;
    import org.springframework.web.bind.annotation.RestController;

    @RestController
    @RequestMapping("/top-level-class")
    @ObfuscateBusinessEvent(sensibleInput = {"$.name", "$.identityCard"}, sensibleOutput = {"$.identityCard"})
    public class BusinessApiController {

        @PostMapping("/be-sensible")
        public Mono<String> beSensible(@RequestBody User user) {
            String name = user.getName();
            return "{\"user\":\"" + name + "\",\"identityCard\":\"00000001A\"}";
        }

        @PostMapping("/get-be-sensible")
        public Mono<String> getBeSensible() {
            String name = user.getName();
            return "{\"user\":\"" + name + "\",\"identityCard\":\"00000001A\"}";
        }
    }

    @Data
    @AllArgsConstructor
    public static class User {

        private String name;

        private String identityCard;
    }

For the *beSensible(…​)* method, in the input parameters, both fields will be hidden. The input data event will have this form for any request:

    {
      "user": "****",
      "identityCard": "****"
    }

And for the body of the response, the field ***identityCard*** will be hidden. The output data event will have this form:

    {
      "name": "Paul",
      "identityCard": "****"
    }

**Example of the `ObfuscateBusinessEvent` annotation at the method level.**

First, the path has to be defined inside the list of the functional logged endpoints as follows:

    darwin:
      events:
        business:
          filter:
            endpoints:
            - /method-level/be-sensible-info

After, the annotation is used for marked the method controller of the endpoint defined in the list:

    import com.santander.darwin.events.business.annotation.ObfuscateBusinessEvent;
    import org.springframework.web.bind.annotation.RequestParam;
    import org.springframework.web.bind.annotation.RequestMapping;
    import org.springframework.web.bind.annotation.RestController;

    @RestController
    @RequestMapping("/method-level")
    public class BusinessApiController {

        @PostMapping("/be-sensible-info")
        @ObfuscateBusinessEvent(sensibleInput = {"identityCard"}, sensibleOutput = {"$.identityCard"})
        public Mono<Strint> beSensible(@RequestParam String identityCard) {
            return "{\"user\":\"Rose\",\"identityCard\":\"identityCard\"}";
        }
    }

For the input parameters, the field ***identityCard*** will be hidden. The input data event will have this form:

    {
      "identityCard": "****"
    }

For the body of the response, the fields ***identityCard*** will be hidden as well. The output data event will have this form:

    {
      "user": "Rose",
      "identityCard": "****"
    }
