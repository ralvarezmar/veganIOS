# Arsenal Brazil Backend 1.9.x to Arsenal Gluon Backend 3.7.0 Migration Guide

This guide is intended to show the migration of an application generated by the
archetype Arsenal Backend Brazil, version 1.9.x to an Arsenal Gluon Backend
application, version 3.7.0. In this migration, several upgrades and improvements
were made, including the use of Spring 3.

## Update pom.xml

### update parent

Initially we must change the parent to version 3.7.0

```xml
<parent>
    <groupId>com.santander.ars</groupId>
    <artifactId>gln-back-arsenal-backend-lib-parent</artifactId>
    <version>3.7.0</version>
</parent>
```

### remove properties

Since we have the properties defined in the parent, we don't need to declare the
maven compiler versions or the build encoding of the project, being able to
remove the following:

```xml
<project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
<maven.compiler.target>11</maven.compiler.target>
<maven.compiler.source>11</maven.compiler.source>
```

### update dependencies

Arsenal Lib Core and other dependencies that are delivered as arsenal-lib-test
must be removed in archetype and add the starters used in Gluon.

***To remove:***

```xml
<!-- Arsenal Libraries -->
<dependency>
    <groupId>br.com.santander.ars</groupId>
    <artifactId>arsenal-lib-core</artifactId>
</dependency>

<dependency>
    <groupId>br.com.santander.ars</groupId>
    <artifactId>arsenal-lib-test</artifactId>
    <scope>test</scope>
</dependency>
```

***To add:***

```xml
<!-- Arsenal Gluon Starters -->
<dependency>
    <groupId>com.santander.ars</groupId>
    <artifactId>gln-back-arsenal-backend-api-starter</artifactId>
</dependency>

<dependency>
    <groupId>com.santander.ars</groupId>
    <artifactId>gln-back-arsenal-backend-error-starter</artifactId>
</dependency>

<dependency>
    <groupId>com.santander.ars</groupId>
    <artifactId>gln-back-arsenal-backend-telemetry-log-starter</artifactId>
</dependency>

<dependency>
    <groupId>com.santander.ars</groupId>
    <artifactId>gln-back-arsenal-backend-test-starter</artifactId>
    <scope>test</scope>
</dependency>
```

For using Spring 3.x, some Spring dependencies are required, for the correct
functioning of the application, then we must add:

***To add:***

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webflux</artifactId>
</dependency>

<dependency>
    <groupId>org.springframework.security</groupId>
    <artifactId>spring-security-web</artifactId>
</dependency>
```

### update plugins

The Archunit must be changed to use the Gluon component:

```xml
<plugin>
    <groupId>com.santander.ars</groupId>
    <artifactId>gln-back-arsenal-backend-archunit-plugin</artifactId>
    <executions>
        <execution>
            <phase>test</phase>
            <goals>
                <goal>arch-test</goal>
            </goals>
        </execution>
    </executions>
    <dependencies>
        <dependency>
            <groupId>com.santander.ars</groupId>
            <artifactId>gln-back-arsenal-backend-archunit-core</artifactId>
            <version>${revision}</version>
        </dependency>
    </dependencies>
</plugin>
```

It is still necessary to add the following plugin in the pom.xml:

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <configuration>
        <compilerArgs>
            <arg>-parameters</arg>
        </compilerArgs>
    </configuration>
</plugin>
```

## Update Classes

### change javax to jakarta

In imports of classes within the following packages, we must change where is
using javax, for jakarta.

***Packages:***

* model
* controller
* test/client

### change imports from Arsenal libs to Gluon Starters

Some classes use imports from Arsenal libs that we must change to the Gluon
Starters

***YourEntityServiceImpl***

*from:*

```java
import br.com.santander.ars.error.exceptions.BusinessException;
```

*to:*

```java
import com.santander.ars.error.AppArsenalErrorCode;
````

***YourEntityErrorCode***

*from:*

```java
import br.com.santander.ars.error.catalog.ErrorCode;
import br.com.santander.ars.error.conventions.HttpCode;
```

*to:*

```java
import com.santander.ars.error.catalog.ErrorCode;
import com.santander.ars.error.conventions.HttpCode;
```

### remove @EnableArsenalCore annotation

In the ArsenalApplication class, the @EnableArsenalCore annotation must be
removed since we have removed the Arsenal Core lib

## Update Application Properties

### remove Spring Profile Actives

Spring Boot 2.4 has improved the way that application.properties and
application.yml files are processed.

See here for details: [Spring Boot Config Data Migration
Guide](https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-Config-Data-Migration-Guide)

So, if you have, then just remove this entry in the yaml file.

```yaml
  profiles:
    active: test
```
