MongoDB is a NoSQL document oriented database.Arsenal MondoDB was created to
make the generation of a MongoDB project easier.This document aims to present
and assist the process of creating Arsenal MongoDB projects from our Archetype
based on Java 17 and Spring Boot 3. By following this guide, you will have a ready-made
environment for developing Arsenal pattern applications.

## Prerequisites

* JDK 17
* Maven (3.9 or above)
* MongoDB (6 or above)
* IDE (with Maven and JRE configured)

## Create a new Arsenal MongoDB project from Archetype

!!! warning "Archetype Usage"

    New applications should be created using Gluon Portal. Projects generated
    by only the archetype lacks essential SDLC files and configurations and
    should be used only for tests

To complete this guide, you need:

* Open your command terminal (PowerShell, Terminal or Shell)

* Copy the command below:

    ``` { .bash .copy }
    mvn archetype:generate \
    -DarchetypeGroupId=com.santander.ars \
    -DarchetypeArtifactId=gln-back-arsenal-backend-archetype-mongodb \
    -DarchetypeVersion={!include-markdown '../../snippets/versions.md' start='<!tag:back-version>' end='<!end:back-version>'!} \
    -DgroupId=com.santander.ars \
    -DartifactId=arsenal-demo \
    -Dversion=0.1.0-SNAPSHOT
    ```

!!! tip "RELEASE keyword"

    Use RELEASE keyword to always get the latest released version of the archetype

!!! tip "Variables that you need to change"

    __-DgroupId:__ identifier of your application's domain group

    __-DartifactId:__ application artifact identifier

    __-Dversion:__ artifact version

    Do not change **DarchetypeGroupId**, **DarchetypeArtifactId** and **DarchetypeVersion** fields

* Type the Enter screen and wait for the end of the process of making the
process.

* Access the root of the created project (in this case, arsenal-demo):

    ``` { .bash .copy }
    cd arsenal-demo/
    ```

## How to build and run application?

* Invoke maven to automatically generate resources (see section __Contract
First__ and __OAS3__). This will use the OpenAPI Generator to:

    ``` { .bash .copy }
    mvn generate-sources
    ```

* Note that the target/generated-sources/openapi/ folder has been created.
Inside it is source code inside src/main/java:

    ![alt text for screen
    readers](../assets/images/quickstart-tree-mongo-1.png "Quickstart
    Arsenal").

* Let's generate the application build, to make a .jar file of the artifact:

    ``` { .bash .copy }
    mvn clean package
    ```

* Again the /target folder will be populated with more resources:

    ![alt text for screen
    readers](../assets/images/quickstart-tree-mongo-2.png "Quickstart
    Arsenal").

* With the .jar artifact generated, we will now run our application:

    ``` { .bash .copy }
    mvn spring-boot:run
    ```

!!! tip "profiles"

    Project generated by the archetype contains two profiles: the default one
    **application.yml** and a local one **application-local.yml**

    To use the local profile, run with:

    mvn spring-boot:run -Dspring-boot.run.profiles=local

* We will observe our application available at the following address:

``` { .bash }
http://localhost:[port]/[context]/swagger-ui/index.html#/
```

* When you're done exploring Swagger, stop the terminal from unlock the port in
  use.

![alt text for screen readers](../assets/images/quickstart-arsenal-19.png
"Quickstart Arsenal").

!!! tip "Attention!"

        __NOTE 1:__ To close the application and MongoDB press
        ctrl+c

        __NOTE 2:__ MongoDB will use the \tmp\mongotest directory to store its file
        structure (provided in pom.xml). Mongo processes may generate the following
        error: Could not start process: <EOF>. If you encounter this type of problem,
        delete the file structure mounted by MongoDB, located at: \tmp\mongotest
