# Relational Database

Relational Databases can be defined as those based on the concept of tables,
where the attributes of the information being stored are represented by columns
of the table and each row of the same represents a different record. Typically
we can build relationships between tables, hence the name of relational
databases.

The architecture provides a persistence capability that seeks to abstract and
facilitate the application's interaction with specific aspects of relational
databases. This article deals with the necessary modeling to map Java classes to
entities of a relational database. Be sure to read the section on the Repository
Pattern to understand how to perform operations (queries, insertions, etc.) in
the database.

## Entities

The data models we work with in our applications, such as Customer, are known as
entities in a relational database. It is through entities that we can map
attributes of a Java class to columns of a table in a database. This mapping is
done through annotations, which we will see in more detail in the examples
below.

### Annotations

#### @Entity

The __@Entity__ annotation is used to indicate that a given class should be
treated as a database entity.

#### @Table

The __@Table__ annotation allows indicating the name of the database table in
which the entity must be stored. When not informed, it is assumed that the table
name will be exactly the same as the class name. To ensure greater clarity and
ease of change in the future (without the need to refactor the code), we
recommend always indicating the table name through this annotation, as in the
example below:

``` { .java .copy }
@Entity
@Table(name="customers")
public class Customer {}
```

#### @Column

The __@Column__ annotation is used to map Java class attributes to the
respective database columns. Similar to what we saw in the case of tables, the
__@Column__ annotation can be used to define the database column name, and here
we also recommend that this procedure is always performed. We can also use this
annotation to configure other column parameters such as its size, whether it can
receive null values, whether it is unique, among others.

``` { .java .copy }
@Column(name = "customer_id", length = 11, nullable = false, unique = true)
private Long id;
```

In the example above, we are specifying that the id field of the Customer class
will be stored in the customer_id column of the database. We are also indicating
that this field must be 11 characters long, cannot be null and must be unique.

#### @Transient

It's common to have attributes in the Java class that don't need to be mapped to
columns in the database. For example, imagine that the database stores a
customer's date of birth, but the Java class is built with an age attribute that
already returns the calculated age in years. In such cases, we must annotate
these attributes as __@Transient__, as in the example below:

``` { .java .copy }
@Transient
private int age;
```

### Primary Keys

When working with relational databases it is important to define the primary key
of our table. In this case, we can also use specific annotations to indicate
which attribute of the Java class represents the primary key of the database.

### Annotations

#### @Id

The __@Id__ annotation is used to indicate that a given attribute should be
treated as a primary key:

``` { .java .copy }
@Id
@Column(name = "customer_id", length = 11, nullable = false, unique = true)
private Long id;
```

#### @GeneratedValue

Typically numeric primary keys are automatically generated by the database when
records are inserted into the database. This behavior must be explicitly
indicated with the __@GeneratedValue__ annotation. The use of this annotation
may vary according to the type of database being used, below we present examples
for Oracle and PostgreSQL databases.

``` { .java .copy }
@Id
@GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "CUSTOMER_SEQ")
@SequenceGenerator(sequenceName = "customer_seq", allocationSize = 1, name = "CUSTOMER_SEQ")
private Long id;
```

In Oracle, primary keys are typically fed by a Sequence, this behavior is
configured via the additional __@SequenceGenerator__ annotation.

``` { .java .copy }
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

### Compound Keys

#### @EmbeddedId and @Embeddable

When working with relational databases, it is also very common to have the need
to use composite primary keys. Composite keys must be modeled in a separate
class that contains the fields of the key in question, and we must use the
__@EmbeddedId__ and __@Embeddable__ annotations to indicate the attribute that
represents the composite key and which class implements it, respectively. In the
example below, the Customer class has a composite key implemented by the
CustomerId class:

``` { .java .copy }
// Class that uses a composite key
@Entity
public class Customer {

    @EmbeddedId
    private CustomerId customerId;
}

// Class that implements the composite key
@Embeddable
public class CustomerId {

    private Long cpf;
    private String rg;
}
```

## Relationships

Just as relational databases allow the creation of relationships between their
tables, we must also indicate the relationships between the entities that
represent these tables.

### Annotations

#### @JoinColumn

In a relationship between two entities, the __@JoinColumn__ annotation is used
to specify the name of the column that will contain the foreign key of the
relationship.

Consider the relationship below between customer and address entities. In this
relationship, a customer can have multiple addresses, but an address can only
belong to a single customer; this is expressed by the presence of a customer_id
column in the address entity.

![alt text for screen readers](../../assets/images/persistence_1.png
"Persistence").

In code, this relationship should be represented as follows:

``` { .java .copy }
@JoinColumn(name = "customer_id")
private Customer customer;
```

When the foreign key is a composite key, the @JoinColumn annotation must be used
inside the @JoinColumns annotation, as in the example below:

``` { .java .copy }
// Example of a foreign key composed of attributes "id" and "cpf"
@JoinColumns({
    @JoinColumn(name = "customer_id", referencedColumnName = "id")
    @JoinColumn(name = "customer_cpf", referencedColumnName = "cpf")
})
private Customer customer;
```

#### MappedBy attribute

When we want to specify a bi-directional relationship between two entities, the
entity that owns the relationship must be marked with the mappedBy attribute. In
the above example between customer and address, the bi-directional relationship
would be specified as follows:

``` { .java .copy }
public class Customer {
    // mappedBy="customer" because in the Address class the attribute of type Customer has the name "customer"
    @OneToMany(mappedBy = "customer")
    private List<Address> addresses;
}

public class Address {
    @ManyToOne(cascade = CascadeType.ALL)
    @JoinColumn(name = "customer_id")
    private Customer customer;
}
```

#### Cascade attribute

This attribute indicates the behavior that will be applied to the related entity
when some operation is performed with the entity that owns the relation.

The most common values applied to this attribute are:

| CascadeBy | Description |
|---|---|
| ALL | All operations done on the owning entity will be reflected on the related entity. |
| MERGE | The related entity will be updated when the owner is also updated. |
| PERSIST | The related entity will be persisted when the owner is as well. |
| REMOVE | The related entity will be removed when the owner is removed. |

!!! tip "Attention!"

    The cascade attribute is specified in relation annotations,
    see for example the @ManyToOne annotation in the examples above.

#### @OneToOne

The __@OneToOne__ annotation is used to specify that the class has a one-to-one
relationship with the class that owns the relationship.

``` { .java .copy }
public class Customer {
    // There will only be one record in the address table for each customer
    @OneToOne
    @JoinColumn(name = "ADDRESS_ID")
    private Address address;
}
```

#### @OneToMany

The __@OneToMany__ annotation is used on datasets (eg List) to specify a
one-to-many relationship with the owning class.

``` { .java .copy }
public class Customer {
    // A customer (customer) can have several addresses (address), and an address only belongs to a single customer.
    @OneToMany
    private List<Address> addresses;
}
```

#### @ManyToMany

The @ManyToMany annotation is similar to the above case, but indicates a
many-to-many relationship.

``` { .java .copy }
public class Customer {
    // A customer may have multiple addresses, and addresses may be shared between different customers.
    @ManyToMany(cascade = CascadeType.ALL)
    private List<Address> addresses;
}
```

#### @ManyToOne

It is the inverse case of the @OneToMany annotation, which must be placed on the
opposite side of the relation.

``` { .java .copy }
public class Address {
    // Multiple addresses can belong to a single customer
    @ManyToOne(cascade = CascadeType.ALL)
    private Customer customer;
}
```
