# Using Lombok

## How to prepare my IDE to use Lombok?

As Arsenal already provides the necessary dependencies for consuming the Lombok
library, you just need to use the correct plugin in your IDE so that it can interpret
the annotations and locate the operations that were abstracted:

* Eclipse IDE
* IntelliJ IDE
* VS Code IDE

## How to use Lombok in my code?

Once the respective Lombok plugin is installed in your favorite IDE, and once
Arsenal Backend already delivers the capabilities of using Lombok, it is only
necessary to infer the desired annotations in the code that you would write common
code, for example:

Imagine a class that represents a DTO request model. Note that in a conventional
approach, we declare at least one constructor and the Get and Set accessors, generating
additional lines that are totally irrelevant for the purpose of delivering the project:

``` { .java }
package br.com.santander.ars.app_log_test.model.dto;

import com.fasterxml.jackson.annotation.JsonCreator;
import com.fasterxml.jackson.annotation.JsonProperty;
import java.io.Serializable;

/** Data Transfer Object (DTO) representing Example requests. */
public class ExampleRequestDTO implements Serializable {

  private static final long serialVersionUID = 1L;

  /** Other info about the Example. */
  private String otherInfo;

  /**
   * Builder for the class.
   *
   * @param otherInfo of the new example.
   */
  @JsonCreator
  public ExampleRequestDTO(@JsonProperty("otherInfo") String otherInfo) {
    this.otherInfo = otherInfo;
  }

  /** Getter otherInfo. */
  public String getOtherInfo() {
    return otherInfo;
  }

  /** Setter otherInfo. */
  public void setOtherInfo(String otherInfo) {
    this.otherInfo = otherInfo;
  }
}
```

Now based on the same scenario, applying the use of Lombok, notice how the use of
the correct annottations considerably reduces the amount of lines generated.
This brings better code readability and increases developer productivity:

``` { .java }
package br.com.santander.ars.br.com.santander.ars.dto;

import lombok.Setter;
import lombok.Getter;
import lombok.Builder;
import lombok.NoArgsConstructor;
import lombok.AllArgsConstructor;

import java.io.Serializable;

/** Data Transfer Object (DTO) representing Example requests. */
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
public class ExampleRequestDTO implements Serializable {

  private static final long serialVersionUID = 1L;

  /** Other info about the Example. */
  private String otherInfo;
}
```

!!! tip "To think..."
    Think of the same example used previously, but now with 15 attributes in the
    class. Think of the lines generated with constructors, getters, setters,
    equals, hashcode...

## How is the test coverage of the methods generated by Lombok?

Probably you've already put some efforts into code coverage with unit tests
in methods getter(), setter(), hashCode(),equals(), builder().
Using the Lombok library allied with Cucumber,
a kind of "automatic coverage" occurs through BDD scenarios.
