# KAFKA

[**Apache Kafka**](https://es.wikipedia.org/wiki/Apache_Kafka) it is a message brokering project. For the generation and consumption of messages following the pattern [PUB/SUB](https://en.wikipedia.org/wiki/Publish%E2%80%93subscribe_pattern).

## Summary

Library in charge of creating Kafka Producers and Consumers. The purpose of creating this library is to make it easier for developers to create/handle and expose more information about the errors that we have encountered when working with Kafka.
The presented documentation contains several practical examples of how to work with the library as well as some common test cases.
For its construction it is used as a base library [Kafka-node](https://www.npmjs.com/package/kafka-node).
It has support for Consumers, Producers, Stream Consumers, Stream Producers.

> Important: This library has .d.ts declaration files so that it can be instantiated from typescript.

## Installation

```sh
npm i -S @darwin-node/kafka
```

## Producer

It is the element that generates the data, it does not do it directly to a subscriber. It does so through **topics** to which 0 to N items can be subscribed.
In the following example we are going to create a **Producer** to which we will pass a connection configuration.
**To know what parameters we can pass to the constructor, we can consult the definition file that contains the library.**

### Productor en Javascript

```js
const config = {
  kafkaHost: 'sanlbekfkkd0001.santander.dev.corp:9092,sanlbekfkkd0002.santander.dev.corp:9092,sanlbekfkkd0003.santander.dev.corp:9092'
};
const { Producer } = require('@darwin-node/kafka');
const producer = new Producer(config);
```

With this we would have already created the element, however, when using an asynchronous connection we run into a problem.
**What happens to the messages that my application has generated until the element is connected?**.
To solve this we will use two elements a **cache** to store the data pending delivery and we will subscribe to the event generated by the producer to know when to send.
To subscribe to the event we use the pattern of [publisher/subscriber](https://docs.microsoft.com/es-es/azure/architecture/patterns/publisher-subscriber) with the library [pubsub-js](https://www.npmjs.com/package/pubsub-js).

Next, we are going to continue with the example and we are going to subscribe to the **READY** event generated by the producer we have created.

```js
const canSend = false;
const config = {
  kafkaHost: 'sanlbekfkkd0001.santander.dev.corp:9092,sanlbekfkkd0002.santander.dev.corp:9092,sanlbekfkkd0003.santander.dev.corp:9092'
};
const { Producer } = require('@darwin-node/kafka');
const producer = new Producer(config);

const onProducerReadyHandler = () => {
  canSend = true;
};

this.producer.suscribe(this.producer.topics.ONPRODREADY, onProducerReadyHandler); // we subscribe to the event and we say which is our handler of said event.
```

Finally, we can be given the case that we send messages before the connection is made (the case of logs).
In this case we would lose the messages prior to the connection, however there is a trivial solution for this problem, we temporarily store the messages to be sent in memory and once the connection is established we refresh.

Next we will continue with the example introducing this solution.

```js
const canSend = false;
const config = {
  kafkaHost: 'sanlbekfkkd0001.santander.dev.corp:9092,sanlbekfkkd0002.santander.dev.corp:9092,sanlbekfkkd0003.santander.dev.corp:9092'
};
const { Producer } = require('@darwin-node/kafka');
const producer = new Producer(config);
const queue = [];

const send = (data) => {
  if (!canSend) {
    this.queue.push(data);
  } else {
    this.producer.send({ message: data.message, data.topic }); // IMPORTANT
  }
};
const flush = () => {
  while (queue.length) {
    send(queue.shift());
  }
};
const onProducerReadyHandler = () => {
  canSend = true;
  flush();
};

producer.suscribe(producer.topics.ONPRODREADY, onProducerReadyHandler); // we subscribe to the event and we say which is our handler of said event.

module.exports = {
  send
};
```

> IMPORTANT: In order to send data, we must construct an object with the attributes message and topic, so that it can be sent to different topics using the same producer, and that the customer decides to send to it.

### Productor en Typescript

This is a basic producer example using **typescript**. We create an instance, and we subscribe to the ONPRDREADY event that tells us when the Producer can send messages.

```sh
import { Producer, KafkaClientOptions } from '@darwin-node/kafka';
let options: KafkaClientOptions;
options = {
  kafkaHost: 'localhost:9092'
}
const producer = new Producer(options);
const queue = [];
let n = 0;
const onProducerReadyHandler = () => {
  console.log('Producer Ready');
  setInterval(() => {
    console.log('Sending')
    const data = { message: `hola ${n++}`, topic: 'nuar-mobile-log'};
    console.log('Sending', data);
    producer.send(data);
  }, 300);
};

producer.suscribe(producer.topics.ONPRODREADY, onProducerReadyHandler);
```

## Consumer (Subscriber)

It is the element that is responsible for consuming the messages.
Next we will create a Consumer, this uses the PUB / SUB pattern for its operation. **To know what parameters we can pass to the constructor, we can consult the definition file that contains the library.**

### JavaScript

Basic consumer example, connects to a topic and receives messages.

```js
const { Consumer } = require('@darwin-node/kafka');
const payload = [{ topic: 'nuar-mobile-log', partition: 0 }]; // it can be a string or an array
const consumerOpts = { autoCommit: false };
const consumer = new Consumer({
  kafkaHost: 'localhost:9092'
}, payload, consumerOpts);

consumer.on('message', (message) => {
  console.log(message);
});
consumer.on('error', (error) => {
  console.log(error);
});
consumer.on('offsetOutOfRange', (error) => {
  console.log(error);
});

```

### Typescript

This example is the same as for Javascript except for the import and the typing that helps us to know the structure of the configuration or shipping objects.

```js
import { Consumer, ConsumerOptions, KafkaClientOptions, OffsetFetchRequest } from '@darwin-node/kafka';
const topicTest = 'nuar-mobile-log';

let clientOpts: KafkaClientOptions;
clientOpts = {
  kafkaHost: 'localhost:9092'
};
let payloads: OffsetFetchRequest;
payloads = {
  topic: topicTest,
  partition: 0
};
let consumerOpts: ConsumerOptions;
consumerOpts = { autoCommit: false };
const consumer = new Consumer(clientOpts, [payloads], consumerOpts);
consumer.on('message', (data) => {
  console.log(data);
});
consumer.on('error', (data) => {
  console.log(data);
});
consumer.on('offsetOutOfRange', (data) => {
  console.log(data);
});
```

## Streams

**Real-time data processing** (message to message) continuously and concurrently.
**Process based on reading messages** from a **source** topic, performs some type of operation on that data and writes what is obtained in a **destination** topic.

### Tipos de Streams

Documentation of [fs](https://nodejs.org/api/fs.html), [zlib](https://nodejs.org/api/zlib.html) y [net](https://nodejs.org/api/net.html)

- Writable: Stream into which data can be written.

```js
fs.createWriteStream()
```

- Readable: Stream from which data can be read.

```js
fs.createReadStream()
```

- Duplex: Transfers that are legible and legible.

```js
net.Socket
```

- Transform: Streams que pueden modificar o transformar los datos a medida que se escriben y leen.

```js
zlib.createDeflate()
```

## Stream producer

In this example, we read from a json file and insert it into kafka. Since it is an array, we are going from object to object. **To know what parameters we can pass to the builder we can consult the definition file contained in the library.**

### Stream producer Javascript

```js
const { ProducerStream } = require('@darwin-node/kafka');
const { Transform } = require('stream');
const fs = require('fs');
const JSONStream = require('JSONStream');
const readStream = fs.createReadStream('jsonexample.json', {
  encoding: 'utf8'
});
let kafkaClientOptions = {
  kafkaHost: 'localhost:9092'
};
let producerOptions = {};
let producerStream = null;

const transform = new Transform({
  objectMode: true,
  decodeStrings: true,
  transform (text, encoding, cb) {
    console.log(`pushing ${JSON.stringify(text)} to nuar-mobile-log`);
    cb(null, {
      topic: 'nuar-mobile-log',
      messages: text
    });
  }
});
producerStream = new ProducerStream(kafkaClientOptions, producerOptions);

readStream.pipe(JSONStream.parse('*')).pipe(transform).pipe(producerStream);
setTimeout(() => {
  readStream.close();
  producerStream.close();
}, 3000);
```

## Stream consumer

In this example, we read through a Kafka stream, and process it.
It is possible to stop the flow and resume it as required by our business logic.
**To know what parameters we can pass to the builder we can consult the definition file contained in the library.**

### Stream consumer Javascript

```js
const { ConsumerGroupStream } = require('@darwin-node/kafka');
const { Transform } = require('stream');
let consumerGroup = null;
const transform = new Transform({
  objectMode: true,
  decodeStrings: true,
  encondig: 'utf8',
  transform (data, encoding, cb) {
    console.log('I recive: ', data);
    consumerGroup.commit(data, true);
    cb();
  }
});
const kafkaClientOpts = {
  kafkaHost: 'localhost:9092'
};
consumerGroup = new ConsumerGroupStream(kafkaClientOpts, transform, 'nuar-mobile-log');

setTimeout(() => {
  console.log('After 10 seconds stop the stream');
  stream.pause();
}, 10000);
setTimeout(() => {
  console.log('After 20 seconds resume the stream');
  stream.resume();
}, 20000);
```

### Stream consumer Typescript

This example is the same as we used above.

```js

}

  objectMode: true,
  decodeStrings: true,
  encondig: 'utf8',

  }

```
