## Create

<div class="cards row-2" markdown>

- ### Event proposal

    ---

    Create a new event **proposal** when a new need is born. For that, we will create a issue on Github, so governance team can check if the validation is correct or a new version needs to be proposed.n.

    <br>

    ---

    [:material-arrow-right: Start journey](proposal/index.md){ .md-button }

- ### Event definition

    ---

    Complete the event **definition** in order to indicate the structure of the events for the created proposal. Here we will indicate the characteristics of the events in order to meet the requirements of the proposal.

    <br>

    ---

    [:material-arrow-right: Start journey](definition/index.md){ .md-button }

- ### Event deployment
  
    ---

    **Deploy** an event based on a previous event definition. Different companies or application will be able to deploy the same event definition on different ways, but they will always respect the defined contract in the event definition.

    <br>

    ---

    [:material-arrow-right: Start journey](deployment/index.md){ .md-button }

- ### Event subscription
  
    ---

    Create a new **Subscribe** of an event. Here we will indicate the characteristics of subscribing to an event.

    <br>

    ---

    [:material-arrow-right: Start journey](subscription/index.md){ .md-button }
