# Full template

More structured model and very similar to the traditional ***Git Flow***.

With this model, it is possible to structure deliverables so that each new version can contain more than one change, whether they are new features or ***bug***.

In addition, it is possible to make urgent deliveries, also known as ***hotfix***, and that escape the conventional flow.

This model makes sense for library projects that fall into the following scenarios:

- Many developers working simultaneously on different deliverables.
- Deliveries require multiple different changes.
- It has a validation flow that does not allow changes to be delivered before an acceptance, causing the accumulation of changes to be delivered.
- Has the need to make urgent deliveries that are not within the conventional flow.
