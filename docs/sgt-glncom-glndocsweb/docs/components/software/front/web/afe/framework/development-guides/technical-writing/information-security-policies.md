# Information Security Policies for Technical Writing

Have you ever used a text checking tool or even an external artificial intelligence assistant, such as ChatGPT, to summarize a long text or improve a paragraph for documentation?

Although these tools help a lot on a day-to-day basis, we must be careful with their use when we are dealing with internal Santander information.

## Classification of information

Information is classified according to its sensitivity and confidentiality. Of those, let's take a look at which ones we're going to use to classify the content of a documentation:

- **Public**: Any data or information that can be obtained from other external channels or that has been officially published and distributed to the public by the bank.
- **Internal**: Any data published through internal channels and available only to bank employees.
- **Restricted Confidential**: Any data that reflects Santander's internal knowledge, obtained as a result of analysis or research, which presupposes a competitive advantage for the bank.

Except for public information, other classifications of information should **not** be trafficked to external tools, even if they seem harmless, such as grammar checking or code improvement.

In general, we are not aware of how the data trafficked in these tools is processed and retained and its use in any internal, confidential, confidential and secret information, constitutes a breach of confidentiality and is subject to disciplinary measures.

## Recommended use of external tools

The use of external tools is not prohibited, if the privacy and confidentiality policy is respected. Let's look at some examples of proper use:

- Use content generation tools to summarize public and external documentation, such as summarizing a long excerpt from an ECMA specification to include in some internal documentation;
- Use an artificial intelligence assistant to research concepts or best practices, such as asking ChatGPT how to explain in simplified words what front-end architecture is.

Now, here are examples of what **not** to do:

- Copy a ***.json*** file with sensitive information such as social security numbers and names to an online tool that converts ***.json*** files into objects.
- Copying a piece of code from some internal application to *ChatGPT*, asking it to refactor the code or improve it.
- Use a third-party grammar review tool to verify an excerpt of internal documentation of a strategic Santander solution.
