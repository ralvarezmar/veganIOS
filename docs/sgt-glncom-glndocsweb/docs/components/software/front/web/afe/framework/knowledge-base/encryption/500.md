# How to Troubleshoot "500 Internal Server Error After Key Exchange"

Some applications may encounter the [500 Internal Server Error](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/500) error when calling a gateway (Zup, Apigee) right after performing the key exchange.

> It is worth noting that the [500 Internal Server Error](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/500) error is a server-side error.
> Which can be caused by intermittency or by some payload data that is being passed erroneously on the front-end.

## Contextualization

In order for an application to use the encryption and requests feature correctly.

It needs to be authenticated in the correct context, in this case when there is a mixture of contexts such as Apigee/Zup and Zup/Apigee in the same project, without coexistence, a mixture of contexts **occurs**

If you are using coexistence, just follow our configuration documentation [Zup and Apigee](../../development-guides/authentication/index.md).

## Solution

It is necessary to check which call is being used in the ***encryption.config.ts***, it has to be pointed to the alias of the desired gateway according to the AFE, using the ***appkey*** of the gateway of the correct context.

``` TS
import { EncryptionConfig, Storages } from '@afe/encryption';

export const encryptionConfig: EncryptionConfig = {
    url: '/hub-url/cryptographic-security/<YOUR_VERSION_API>/key/public/js?gw-app-key=<YOUR_APP_KEY>',
    systemCode: '<YOUR_SYSTEM_CODE>',
};
```

Check if there is the configuration of the coexistence in the ***authentication-legacy.config.ts*** file and check the values correctly.

Do not confuse the ***appKey*** and ***zupAppKey***, if you are not using the coexistence this migration has to be done.

``` TS
import { AuthenticationLegacyConfig } from '@afe/authentication/legacy';

export const legacyAuthConfig: AuthenticationLegacyConfig = {
  urlsToIntercept: [
    '/apigee-url',
  ],
  urlLogin: '/hub-url/auth_convivencia/v1/token',
  urlLogout: '/hub-url/auth_convivencia/v1/logout',
  appKey: '[YOUR_APP_KEY]',
  clientId: '[YOUR_CLIENT_ID]',
  zupAppKey: '[YOUR_ZUP_APP_KEY]',
}
```

> If, after this change, the error "***403 occurs in the exchange of keys in zup***", follow the documentation [Application and Consumption Registration API - Zup.] (<https://confluence.santanderbr.corp/display/PADROESARQINT/Suporte>)
