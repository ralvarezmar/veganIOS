# Go Beyond the Basics – Additional Tips

## Tone & Content

- Be conversational and friendly without seeming aloof
- Don't pre-announce features that don't exist yet
- Links should contain descriptive text, such as "for information, see __load balancing__." Don't use link text without information, such as "see __this page__"
- Use accessible writing: For screen readers, avoid CamelCase and capitalize all the letters of a word (e.g., "click HERE")
- Avoid terms that might not make sense if they're automatically translated, such as "workaround." In this way, we facilitate internationalization.

## Language & Grammar

- Always write in the second person, avoid using "we" and prefer 'you'. As an example, avoid "we're going to run the program" and use "you're going to run the program" and "run the program."
- Use third person, such as "the user runs the system" only to refer to those who use the developed system, never to refer to those who will read the documentation and perform the steps.
- For lists, choose numbered lists for sequences and bulleted lists for the rest of the lists.

## Images

- Do not use screenshots of text, code, or terminal outputs. Use the actual text.
- For diagrams, use SVG files, which remain sharp when you zoom in on the image.
- For animations and videos, don't use animated GIFs. Prefer more resource-efficient formats such as MP4.
